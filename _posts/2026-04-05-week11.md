## Bazaar vs Cathedral

In my opinion, the cathedral format seems to be what most students consider standard in the programming field (me included). In my opinion, the bazaar model works better as it incentives constant collaboration and progress. A core part of the bazaar model that I did not consider was protocol for releasing issues rather than abandoning them. To be fair, it does seem like a part of the model that doesn't always get correctly implemented. Sure, keeping issues open with the relevant comments could count since it ensures any future collaborators have access to address the issue. However, it also seems as though there are instances where issues are readily abandoned because no one wants to respect the claiming of an issue in the first place. A good portion of Pandas issues have been "taken" by users who then never circled back or get started on with no indication. In this way, it becomes a free for all where you cannot actually tell which issue is free and just hope that you solve it before someone else does. This feels like the software version of ticket scalpers.

In regards to AI, the cathedral format does seem to crumble easier. Besides just the accuracy issues, there would be a problem legally speaking if one were to allow their code to become part of the AI's development (aka privacy issues). On the other hand, the bazaar model wouldn't crumble but it also wouldn't thrive in my opinion. Sure, using AI to understand certain concepts can be nice but at a certain point, asking AI to fix the entire problem would negate the point of being in a community. If transparency and limits are defined in the code of conduct, it could still be a useful tool.
